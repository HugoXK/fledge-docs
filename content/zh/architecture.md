# 架构

Fledge 是一个 Node 服务，负责编排隔离的 FlyBot agent。服务拥有控制台、任务队列、GitHub 集成、模型代理与审计记录；它本身不执行用户仓库。

## 原则

- **审批有范围。** Fledge 的审批只授权 Fledge 本身，不为其他产品签发权限或会话。
- **由人合并。** 每个任务只创建一个聚焦的 Pull Request；不推送默认分支、不强推、不合并。
- **平台不是代码运行器。** Fledge 编排 agent；agent 在仓库自己的容器中工作。
- **每仓库隔离。** 容器、数据卷、网络、bridge token 与模型代理都限定在一个仓库内。

## 组件

| 组件 | 职责 |
| --- | --- |
| Web 控制台 | 用户、仓库、任务、计划、审查、设置与审计 |
| 任务队列 | 持久队列、租约、心跳、超时与恢复 |
| FlyBot bridge | 将任务交给隔离的 FlyBot 实例并回收结果 |
| 模型代理 | 注入用户/任务 `flg_` token，计量平台配额 |
| GitHub 集成 | OAuth、仓库 token、PR、检查与合并状态 |
| 审计与账本 | 任务、成本、审批、token 与操作记录 |

## 任务生命周期

```
创建任务 → 计划 → 人工批准 → 隔离执行
        → 失败测试 → 修复 → 项目检查 → Pull Request
        → 人工审查 → 合并（或关闭）
```

计划在执行前可见；高风险操作需要批准。失败任务记录失败类别、重试次数以及是否需要人工处理。运行中的任务有硬超时与无心跳停滞超时。

## 隔离

每个仓库拥有独立容器与私有数据卷。模型代理注入任务范围的 `flg_` token，实例不能使用操作者的平台 Key。bridge token 限定在仓库范围，且不会发送给 agent。CPU、内存、PID 与文件系统挂载均受限；停止或删除一个仓库只影响该容器。

## 数据

核心表覆盖用户、仓库、任务、计划、运行、token、审批、配额账本与审计。SQLite 使用 WAL、外键与事务迁移。控制面数据库与 `TOKEN_ENCRYPTION_KEY` 必须分开备份：没有密钥，数据库无法解密仓库 token 或用户模型 Key。

## 信任边界

- GitHub token、用户模型 Key、SMTP 凭据与会话密钥在控制面加密保存。
- 仓库容器不持有长期 GitHub 凭据，也不持有平台模型 Key。
- 用户提供的 URL、分支名、仓库名与回调正文都是不可信输入，使用前必须校验。
- 合并权始终属于仓库维护者；Fledge 不合并自己的 Pull Request。
