# Fledge

Fledge 是托管式仓库迭代服务。连接一个 GitHub 仓库，描述一个目标，Fledge 返回一个可审查的 Pull Request，并附上决定是否合并所需的证据。合并始终由人完成。

## 为什么使用 Fledge

- **每仓库隔离。** 每个托管仓库运行在独立容器中，拥有私有数据卷、网络、bridge token 与模型代理。
- **证据，而不是演示。** 任务从失败测试开始，记录修复、运行项目检查，并创建一个聚焦的 Pull Request。
- **人工控制。** Fledge 不推送默认分支，不合并，也不绕过审查；由仓库所有者决定。
- **可审计的成本。** 模型花费按用户、仓库与任务计量；初始 1 元由平台承担，之后使用用户自己的模型 Key。

## 工作方式

1. **连接仓库。** 使用 GitHub 登录并提交申请；管理员审批后，连接一个或多个仓库。
2. **描述一个目标。** 为缺陷、能力或文档变更创建一个任务。一个任务是一个工作项，而不是开放式 Agent 会话。
3. **审查计划。** Fledge 规划失败测试、最小修复与将要运行的检查；高风险操作等待批准。
4. **隔离执行。** FlyBot agent 在仓库自己的容器中工作；模型代理计量用量，GitHub 凭据不进入工作区。
5. **审查 Pull Request。** Fledge 创建一个 PR，包含 diff、测试证据与 CI 状态；维护者审查并合并。

## 它不是什么

- 不是代码运行器：Fledge 编排 agent，不直接执行用户仓库。
- 不是自动合并机器人：Pull Request 才是交付物。
- 不替代 GitHub 权限：仓库访问仍由 GitHub 授予。
- 不是公开游乐场：托管服务采用申请制，需要管理员审批。
