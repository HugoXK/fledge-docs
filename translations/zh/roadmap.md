# 路线图

Fledge 的定位是**受治理的托管仓库团队**，不是另一个编码 Agent。差异化在于每仓库隔离、明确的 Chief/Lead 分工、每一步的人工控制，以及可审查的审计与成本轨迹。

当前方向：

1. **异步工作与实时控制面**：任务在后台执行，控制台持续显示计划、进度、成本与阻塞。
2. **计划与权限门**：高风险操作在开始前需要人工批准。
3. **可恢复运行**：检查点、租约与恢复，避免长任务因重启丢失。
4. **证据优先审查**：diff、测试、CI、风险等级与成本一起进入审查。
5. **隔离、密钥代理、预算与审计**：每仓库独立环境，凭据不进入执行环境。

## 不在范围内

- 自动合并或绕过仓库审查。
- 替代 GitHub 的权限模型。
- 把平台变成通用代码运行器。
- 在没有人工批准的情况下执行高风险变更。

路线图会随实际运行与审查结果调整；未完成的能力不会在文档中写成已交付。
