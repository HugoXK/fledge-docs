# Fledge 文档

Fledge 是托管式仓库迭代服务：接入一个 GitHub 仓库，描述一个目标，系统在独立环境中完成计划、实现、测试与审查，并创建一个可审查的 Pull Request。合并始终由人决定。

## 工作方式

1. **接入仓库**：通过 GitHub 登录并提交申请，管理员审批后连接一个或多个仓库。
2. **描述目标**：在控制台创建任务，说明要修复的缺陷或要增加的能力。
3. **隔离执行**：每个仓库运行在独立容器中，拥有独立的数据卷、网络、模型代理与凭据。
4. **提交证据**：系统先编写失败测试，再实施最小修复，运行项目检查，并创建一个 PR。
5. **人工审查**：维护者阅读 diff、测试与 CI 结果，决定是否合并。

## 核心能力

- **每仓库隔离**：容器、卷、网络、模型代理与凭据均按仓库隔离。
- **证据优先**：失败测试、修复、CI 结果与风险等级一起进入 PR。
- **人工控制**：不合并、不推送默认分支、不绕过审查。
- **成本可审计**：平台额度、模型用量与任务成本均有记录；额度用完后可使用自己的模型服务。
- **凭据加密**：GitHub token 与用户模型 Key 使用 AES-256-GCM 加密，密钥不写入数据库。

## 边界

Fledge 不是代码运行器，也不是自动合并机器人。它编排 FlyBot agent 在独立工作区中工作，并把人放在合并与发布的位置。完整英文参考（API、UI、设计决策、交接文档）见侧栏的“英文参考”。
